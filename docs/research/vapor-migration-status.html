02 / What is left

Two tracks prevent
calling the migration finished.

The checklist has three open gate IDs. B08 and H04 describe the same rollout-and-removal chain; H05 is the separate application/framework boundary.

TRACK A · H05Upstream gap

Finish the Nuxt
application boundary.

Our application already enables vue.vapor: true. Nuxt 4.6.2 still uses that setting for interop: the application root remains VDOM. Its official documentation says: “Full Vapor apps are not yet supported.”

Work needed
  • Use future framework support for a full native app, or deliberately build and maintain a custom Nuxt integration.
  • Prove native bootstrap, real SSR/hydration, page/layout routing, provider injection and disposal in all three engines.
  • Trace and remove remaining framework VDOM paths from the application bundle.
What we can do ourselves

We can prototype custom entries, as the standalone CSR harness already demonstrates. A complete native Nuxt app with SSR would be a separate, currently unsupported integration to validate and maintain. A configuration change or package upgrade alone cannot finish H05.

Support checked on 25 Oct against the official Nuxt 4.6.2 Vapor documentation. Our installed application remains on 4.6.1.

Comparison correction, rejected experiments and validation

Fairness correction: removing Vapor markers alone left Button/Chip using native directive signatures. The VDOM copies now select the existing VDOM ripple export and an equivalent root creation/disposal lifecycle. Types, prepared-source hashes and real ripple/update/remount interactions verify those controls. Earlier VDOM timings and percentages are superseded; the final before and after above both use corrected controls.

The measured owner already uses the selected renderer. Nuxt bootstrap stays outside the timed component mount; converting the application's Nuxt root remains a separate, deferred job.

Rejected: a duplicated static Tree root produced no stable native gain; deferred prefetch setup produced no stable native gain and worse tail latency. Both were reverted. A Table slot fast path also failed replication and was removed. Captured row-key preparation was simplified to an existing lodash accessor and tested, then also reverted: one Table block was flat and native scroller results were inconclusive.

The retained Tree change improves both 32-trial native blocks with a negative paired confidence interval. Intervals use 10,000 deterministic bootstrap resamples of paired median differences. This is a shared-machine lab diagnostic, with load and distributions preserved in the evidence. Builds, suites, typechecks and profiling are idle during latency collection.

The corrected combined run records 1,280 samples, 120 SSR/hydration checks, 60 same-compiler DOM parity checks, 12 directive interaction checks and 30 GC remount cycles per family/variant. All retention gates and real scroll runs pass. Separate profiles and DOM construction probes do not contribute to the timing samples.

What the profiles show: Table still spends work in virtualizer measurement, reactive/prop access and DOM geometry. Pivot spends work in aggregation, index/data construction and virtualization in both renderers. Sampling points to these shared costs; it does not prove that one function explains the renderer gap. Neither the cell-inlining nor key/slot proposals earned a stable final gain, so their extra code was removed.

Cleanup: temporary source copies and generated benchmark outputs were removed after archive verification. Frozen inputs, emitted assets/maps, raw profiles and rejected results remain archived for reproduction; the portable evidence includes the final source hashes and decisions.

Existing Tree update contract: publish the model array after nested item edits to rebuild label/search snapshots. Source references are retained. This round verifies model commits, built-in/custom/async search, collapse, drag and remount; automatic deep metadata refresh remains a separate behavior change.

05 / Decision

Where effort now
has the most value.

There is no need to reopen the completed component conversion or the accepted icon implementation. Keep the agreed app-root deferral while pursuing the measurable local opportunity.

After the measured fixes

Set a representative
acceptance budget.

01
Keep the verified source improvements.

Tree reduces setup work; Pivot and Table overhead remains visible. Rejected experiments are removed; contracts, SSR/hydration and disposal checks pass.

02
Measure real consumer screens.

Warm mount overhead and the emitted inventory remain workload-specific costs. Validate startup, interaction and memory budgets before broad rollout.

03
Keep completion gates explicit.

Authenticated consumer E2E and rollout remain B08/H04. The Nuxt app root remains H05 and stays deferred.

Separate completion work

Resume deliberately.

Nuxt app root: keep H05 deferred. Revisit when Nuxt supports full native apps, or if you deliberately choose to own a custom integration. Current configuration already enables the supported interop mode.

Consumer rollout: choose supported projects and upgrade them individually. Keep compatibility until their callers and application tests are migrated.

Assessment today

The library is ready for continued development and controlled adoption on the tested runtime. More work is needed before declaring the whole application native or the cross-project rollout complete.
